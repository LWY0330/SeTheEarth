### D2 · Witness 上传 = 双轨制(PM 决策,等用户确认)

**为什么双轨**:v2 明确反对 Creator 化,但 Witness 是 v2 的核心(第 10 条核心理念)。完全开放会迅速滑向社交媒体;完全关闭则失去 Witness 价值。

**v1.0 双轨方案**:

| 轨道 | 占比 | 内容来源 | Provenance 标签 | 审核 |
|---|---|---|---|---|
| **A · PGC 编辑轨道** | 70% | 编辑团队 + 外包摄影师 | `editor-collected` | 编辑全权,负责 EXIF + 文案 |
| **B · Witness 邀请轨道** | 30% | 受邀见证者(邀请码) | `invited-witness` | 自动化 EXIF 校验 + 抽样人工 |

**为什么不开放自由注册**:
- v2 第 9 条「注意力属于地方,不属于个人」——自由注册会立即引来流量思维用户
- v2 第 7 条「不讨好但也不摧毁」——UGC 必须有 Provenance 兜底,自由注册短期内难保证
- v1.0 验证产品价值后,v1.x 再分阶段开放

**Witness 邀请机制**:
- 邀请码 100 个,定向发给摄影师 / 旅行博主 / 文化机构 / 海外华人
- 邀请码绑定手机号 + 设备指纹(iOS 端用 identifierForVendor)
- 见证者主页:`witnessing-since 2026-XX-XX / 268 moments / 91 days witnessed`(来自 v2 第 286 行)
- 不显示 Followers / 个人热度

### D3 · 媒体存储架构(PM 推荐,等用户确认)

**核心理念**:Provenance 是 v2 第 215-230 行的核心原则,EXIF 是技术抓手。

#### iOS 端 EXIF 处理流程

```
┌────────────────────────────────────────────────────────────┐
│ 用户在 iOS 端拍照片或从相册选择                                │
└────────────────────┬───────────────────────────────────────┘
                     │
         ┌───────────┴───────────┐
         │                       │
    ┌────▼─────┐           ┌─────▼────┐
    │ 实时拍照  │            │ 相册选择  │
    └────┬─────┘           ┌─────┬────┘
         │                 │     │
    AVFoundation          PHPickerViewController(iOS 14+ 必须)
    .photoOutput          (不能自由访问相册)
         │                 │
         └────────┬────────┘
                  │
         ┌────────▼─────────┐
         │ 提取 EXIF         │
         │ - DateTimeOriginal│ 拍摄时间
         │ - GPSLatitude     │
         │ - GPSLongitude    │
         │ - Make/Model      │
         └────────┬─────────┘
                  │
         ┌────────▼─────────┐
         │ ★ 重写 EXIF       │
         │ - 删除 GPS        │ ← 隐私保护
         │ - 保留 DateTime   │ ← Provenance
         │ - 保留 Make/Model │
         └────────┬─────────┘
                  │
         ┌────────▼─────────┐
         │ 上传到服务端       │
         │ multipart/form-data│
         └────────┬─────────┘
                  │
         ┌────────▼─────────────────────┐
         │ 服务端再次校验                  │
         │ 1. EXIF DateTime 是否在 NOW 窗 │
         │    (≤ 24h,可在 Witness 端放宽)│
         │ 2. 文件 SHA-256 去重           │
         │ 3. 图片合规扫描(NSFW / 版权)   │
         │ 4. 通过 → 写入 Moment 表       │
         │    失败 → 写入 Timeline(归档)  │
         └───────────────────────────────┘
```

#### 服务端存储分层

| 层 | 存储 | 用途 | 保留期 |
|---|---|---|---|
| **热** | Redis / CDN Edge | NOW 24h 内的城市卡片 | 24h 后转入温 |
| **温** | PostgreSQL + S3/OSS | 30 天内 Moment + 索引 | 30 天后归档 |
| **冷** | S3 Glacier / 归档存储 | Timeline 历史归档 | 永久(产品价值所在) |

#### 服务端选型建议(PM 推荐,Week 1 Day 1 做技术 Spike)

| 方案 | 优势 | 劣势 | 推荐度 |
|---|---|---|---|
| **A · Supabase** | Auth + Storage + DB 一体,2 天搭好 | 锁定 Supabase,迁移难 | ⭐⭐⭐⭐⭐ |
| **B · 自建 Node + PostgreSQL + S3** | 完全可控,无锁定 | 2 周才稳定,需运维 | ⭐⭐⭐ |
| **C · Cloudflare Workers + D1 + R2** | 边缘性能好,便宜 | 生态较新,Worker 限制 | ⭐⭐⭐ |

**PM 建议:用 Supabase,理由**:
- 2 周内必须有可工作的后端,Supabase 节省 1 周
- Auth(支持 Magic Link 邮箱 + OAuth)、Storage(S3 兼容)、DB(PostgreSQL + RLS)全套
- Witness 邀请码 + EXIF 验证都可以在 Edge Functions 里实现

#### iOS 端 EXIF 关键实现细节

```swift
// iOS 端 EXIF 处理伪代码
func processImage(_ image: UIImage) async -> MomentUpload? {
    guard let data = image.jpegData(compressionQuality: 0.85) else { return nil }
    let exif = EXIFExtractor.extract(from: data)  // DateTime + Make/Model
    
    // ★ 关键:删除 GPS,保留 DateTime
    let sanitized = EXIFRewriter.rewrite(
        data: data,
        keepDateTime: exif.dateTimeOriginal,
        keepDevice: exif.makeModel,
        removeGPS: true  // 隐私保护
    )
    
    // 校验 NOW 窗口
    guard exif.dateTimeOriginal.isWithin(NOW_WINDOW_HOURS) else {
        return .archive(sanitized)  // 超出窗口 → Timeline 归档
    }
    
    return .upload(sanitized, capturedAt: exif.dateTimeOriginal)
}
```

## 7. v1.0 明确「不做」清单(来自 v2,工程必须遵守)

> 此清单为 PM 与工程的契约,任何"看似有用"的功能需先对照此清单。

### 永久不做(产品边界)

- ❌ 个性化推荐算法(不因为"你喜欢什么"缩小世界)
- ❌ Followers / Following(个人不成为注意力中心)
- ❌ 个人 Like 数 / Creator 排行 / 粉丝数
- ❌ 评论区 / 私信 / 转发 / @提及
- ❌ 城市热门榜 / 城市冲榜
- ❌ 实时新闻推送 / 突发快讯
- ❌ 旅行攻略 / 种草内容
- ❌ AI 生成"真实 Moment"(AI 图不能冒充现场)
- ❌ 旧照片伪装 NOW(必须基于 captured_at)
- ❌ 公开精确 GPS / 街道地址(前台仅城市级)
- ❌ 商业化(v1.0 阶段)
- ❌ 多语言 i18n 满铺(仅中英双语接口)

### v1.0 不做(v1.x 探索)

- ⏸️ Witness 自由注册(必须邀请码)
- ⏸️ 见证者主页可视化(只显示计数,不显示热度)
- ⏸️ 旧照片 Timeline 主动归档(自动归档,可浏览)
- ⏸️ Unknown Coordinate → 真实城市跳转(Week 6 实现基础)

### v1.0 必须做(价值环核心)

- ✅ 12 城每日更新(Context + NOW + Timeline)
- ✅ Witness 上传邀请制(100 个邀请码)
- ✅ EXIF 提取 + GPS 重写 + 服务端验证
- ✅ NOW 窗口判断(基于 captured_at)
- ✅ 城市级 Resonance(回响数 + 城市连接数 + 见证天数)
- ✅ Witnessing since 计数(见证者身份)
- ✅ Provenance 标签(`editor-collected` / `invited-witness`)
- ✅ Unknown Coordinate(陌生感入口)
- ✅ Magic Link 邮箱登录(无密码,符合 v2 克制)
- ✅ Privacy by Design(前台城市级 + 后台验证级分离)

## 8. PM 的几个明确取舍

### 8.1 为什么选 Supabase 而不自建

- **2 周必须可工作**:自建 Node + PostgreSQL + S3 + Auth 至少 3 周稳定
- **Witness 规模有限**:v1.0 只有 100 个邀请码,QPS 不会超过 10
- **Supabase 迁移成本可控**:抽象 API 层,业务逻辑与 Supabase 解耦
- **节省的 1 周**投入给 iOS EXIF 链路的稳定性

### 8.2 为什么 v1.0 不做商业化

- v2 第 7 条「不讨好但也不摧毁」——商业化压力会扭曲产品
- v2 第 9 条「注意力属于地方,不属于个人」——商业化最容易滑向 Creator 经济
- 用户已确认:商业化暂缓,先验证产品价值
- 30 天 KPI 是用户增长 + 价值环验证,不是营收

### 8.3 为什么 v1.0 不开放 Witness 注册

- v2 第 9 条明确反对个人成为注意力中心
- 自由注册会引来流量思维用户,稀释 Witness 价值
- 100 个邀请码 + 编辑 PGC = 70/30 配比,既验证 Witness 又保证质量
- v1.1 根据数据再决定是否扩大邀请规模

### 8.4 为什么 iOS 端只做核心 3 个场景

- v2 第 1 条「远方是感受,不是知识」——克制是产品哲学
- iOS 端核心价值环:**首页 → 城市页 → Witness 上传**
- 1:1 复刻 Web 11 城所有页面,既不现实也违反"少即是多"
- Unknown Coordinate 作为"陌生感入口"是 v2 必备,iOS 必须包含

### 8.5 为什么 Reykjavik 是第 12 城

- 地理与心理距离最远,符合"远方感"
- 极昼极夜提供独特的时间体验
- 已有 Yellow Layer 模板可继承,不增加设计成本
- 与 Kyoto(温)/ Lisbon(暖)/ Khartoum(热)形成"第 4 层:远"
