> 版本：v1（首发版，待评审）
> 日期：2026-08-05
> 作者：Codex（项目所有人 lwy）

> 适用范围：本文件是「看见地球」产品立项后的第一份设计规约，作为后续技术、视觉、交互、内容工作的共同参考基线。所有团队成员（含 AI Agent）应以此为单一事实来源（SSOT）开展工作。

## 0. TL;DR

「看见地球」是一款以**数字屏幕为窗口、让用户重新"看见"地球**为内核的交互式可视化产品。v1 版本以**桌面 Web 端单页应用**形态交付，核心体验是一条**可被控制的时间轴 + 一颗可被旋转缩放的地球**，用户可以沿时间轴拖动，观察地球在昼夜、四季、年际、世纪等不同时间尺度下的形态变化（光照、云层、海冰、植被、城市扩张等数据图层可叠加）。所有复杂功能（标注、收藏、对比、AI 解读、协作）都以「先把地球看清楚」为前提渐进引入。

v1 的成功标准不是功能数量，而是**"用户在第一分钟内能感受到地球的尺度与时间"**这一情感与认知层面的触发。

## 1. 项目定位与愿景

### 1.1 一句话定位
> 把"俯瞰地球"这件人类自古以来的愿望，做成任何一台联网电脑前都能随手打开的、安静的、有耐心的数字体验。

### 1.2 核心价值主张
| 维度 | 价值 |
| --- | --- |
| 情感 | 重新唤起对"我们住在哪"的惊叹与敬畏 |
| 认知 | 把抽象的环境/气候/城市化议题具象化为可观察的变化 |
| 实用 | 给教育、科普、研究、新闻、创作场景提供一块可重复使用的"画布" |
| 美学 | 让数据可视化本身具备可被欣赏的视觉品质 |

### 1.3 设计哲学（v1 内贯彻到底）
1. **地球先于一切**：任何功能如果会让地球从画面中央消失，必须被重写。
2. **时间是第四个维度**：交互的"空间自由"已经普及，"时间自由"才是产品的差异点。
3. **少即是多**：v1 拒绝塞满工具栏；首选是 0~2 个控件就能完成 80% 的事。
4. **默认安静**：无 BGM、无弹窗、无自动播放；用户主动触发才发生。

## 2. 目标与非目标

### 2.1 v1 目标（In Scope）
- 在任意现代浏览器（Chrome / Edge / Safari / Firefox 最新两个大版本）打开即可使用，无需登录。
- 提供 3D 地球，支持鼠标拖拽旋转、滚轮/双指缩放、视角俯仰。
- 提供至少 **3 个时间尺度**的预设时间轴：日（24h 昼夜循环）、年（四季/极昼极夜）、世纪（城市扩张/海冰变化）。
- 至少 **1 套基础图层**（如昼夜光照或云层），可叠加可隐藏。
- 支持用户在地球表面**点击任一点**查看"此刻此地"的时间信息与简短文字描述。
- 全程响应式适配 1280×800 及以上桌面分辨率。

### 2.2 非目标（Out of Scope，v1 不做）
- ❌ 移动端原生 App（响应式 Web 仅做"能用"，不优化触屏）。
- ❌ 用户账号体系、社交、协作、评论。
- ❌ UGC 内容上传、二次创作工具。
- ❌ 真实气象/卫星实时数据接入（v1 使用预渲染/缓存的离线数据切片）。
- ❌ VR / AR。
- ❌ 多语言 i18n（v1 仅简体中文 + 英文双语，留接口不做满铺）。

> 这些非目标是 v1 的"克制清单"。任何 v1.x 增量需求需先确认是否破坏非目标，再决定是否纳入。

## 3. 目标用户与典型场景

### 3.1 用户画像（v1 主目标）
| 画像 | 描述 | 关键诉求 |
| --- | --- | --- |
| **A. 好奇的成年人** | 25–45 岁，对地球/天文/环境议题有业余兴趣 | 打开就能被吸引，能"玩"几分钟能讲出点东西 |
| **B. 教育者/学生** | 中学地理/科学老师、大学生 | 课堂展示、自学复习，截图清晰、术语准确 |
| **C. 创作者** | 视频脚本、播客、写作素材搜集者 | 画面漂亮、可录屏、单帧信息密度可控 |
| **D. 轻度研究者** | 环境/气候/城市话题的科普写作者 | 想看到"某地某时"的具体细节，能引用 |

### 3.2 核心使用场景（v1 必须覆盖）
1. **打开就走**：用户第一次进入页面，不读任何说明，10 秒内开始拖动地球。
2. **昼夜欣赏**：用户把时间轴拖到当地夜间，观察城市灯光的分布与海岸线轮廓。
3. **季节对比**：用户在同一天的不同月份之间来回拖动，对比某地日照时长。
4. **指向提问**：用户点击自己家乡，得到一句话回答（例如"此刻为当地下午 3:42，太阳高度角约 48°"）。

## 4. 用户旅程（v1 必体验路径）

```
进入页 → 地球缓慢自转展示（≤3s） → 时间轴出现 → 用户试探性拖动
  → 感受到昼夜变化 → 缩放到自己所在区域 → 点击 → 浮层出现
  → 关闭浮层 → 切换图层（云/海冰/夜间灯光）→ 截图/录屏 → 离开
```

整个旅程应控制在 **3 分钟以内** 完成所有"惊艳时刻"。

## 6. 非功能需求

### 6.1 性能
| 指标 | 目标 |
| --- | --- |
| 首屏可交互（TTI） | < 3s（4G 网络，中端笔记本） |
| 渲染帧率 | 桌面端 ≥ 60 FPS；缩放/旋转中 ≥ 45 FPS |
| 内存峰值 | < 800 MB |
| 包体（gzip） | 首屏关键资源 < 1.5 MB |

### 6.2 可用性
- 全键盘可达：Tab/方向键可完成"旋转→缩放→拖时间轴→点地点"全流程。
- 不依赖颜色单一通道传递信息（昼夜变化下文字与图标必须有对比度保护）。

### 6.3 可访问性
- 符合 WCAG 2.1 AA 对比度要求。
- 时间轴提供 ARIA `slider` 语义，键盘 ←→ 可逐小时移动。
- 所有交互元素 ≥ 32×32 CSS px 命中区域。

### 6.4 隐私
- v1 不收集任何用户识别信息。
- 唯一允许的"用户数据"是 localStorage 中的视角/图层偏好，不上传。

### 6.5 浏览器与设备
- Chrome / Edge / Safari / Firefox 最新两个大版本。
- 最低分辨率 1280×800，不做触屏优化（v1）。
- 不支持 IE / 旧 Edge Legacy。

## 7. 信息架构

```
看见地球（单页）
├── 首屏画布（全屏）
│   ├── 3D 地球（占满）
│   ├── 顶部 HUD（极薄，30px 高）
│   │   ├── 标题（点击回到初始视角）
│   │   ├── 图层切换（右上，P0=1 个，P1=3 个）
│   │   └── 帮助（? 键打开快捷键说明）
│   ├── 底部时间轴（高 64px，含播放/暂停 + 时间标签）
│   └── 点位浮层（点击出现，含位置名、当地时间、太阳高度、一句注释）
├── 加载层（首屏前 < 2s）
│   └── 进度环 + 一句话文案
└──（隐藏）设置抽屉（仅 P1 引入）
    └── 分辨率、帧率、URL 复制、关于
```

> **设计铁律**：除顶部 HUD、底部时间轴、点位浮层外，任何元素**不能常驻遮蔽地球**。

## 8. 交互设计原则

1. **世界坐标系**：所有交互以"地球"为参照系，相机是"观察者"，UI 是"工具"。HUD 是玻璃质感的，避免出现"窗口里的窗口"嵌套感。
2. **手势语义统一**：
   - 左键拖拽 = 旋转
   - 滚轮 / 双指捏合 = 缩放
   - Shift + 拖拽 = 俯仰
   - 双击地点 = 飞过去
3. **时间轴 = 进度条，但更是状态条**：当前时间在刻度上方始终以"当地时间 + UTC"双显示，避免歧义。
4. **不要"弹"**：所有面板/浮层用 150–250ms 缓入缓出曲线（建议 `cubic-bezier(0.22, 1, 0.36, 1)`）。
5. **错误状态也要美**：例如加载失败时显示一颗静止的极简地球 + "信号中断"文案，不弹原生 alert。

## 9. 视觉设计方向

### 9.1 调性关键词
`安静 · 深邃 · 真实 · 一点点未来感`

### 9.2 色彩
- **画布**：纯黑 `#000` 起步（太空感），非纯白/非纯灰。
- **地球海面**：偏冷的深蓝 `#0A1A2F` → `#1B3A5C`，避免 Google Maps 那种亮蓝。
- **地球陆地**：基于真实反照率的低饱和度色。
- **大气层**：边缘冷蓝散射 `#5BA8FF` @ 12% 不透明度。
- **HUD**：玻璃质感 `rgba(8, 12, 20, 0.55)` + 1px 边框 `rgba(255,255,255,0.08)`。
- **文字主色**：`#E8EEF5`；次色：`rgba(232,238,245,0.6)`。

### 9.3 字体
- 中文：`思源宋体` 或 `Noto Serif SC`（宋体让地球感更"书"）。
- 英文：`Inter` 或 `Söhne`（仅 UI 文案）。
- 数字（时间/坐标）：`JetBrains Mono` 或 `IBM Plex Mono`。

### 9.4 动效原则
- 默认相机阻尼：`damping = 0.92`（松手后有惯性）。
- 时间轴播放：默认 1× = 1 秒现实时间 = 1 小时地球时间。
- 不引入任何"装饰性动画"（呼吸光、扫光等）。

### 9.5 图标
- 一套 24px 单色线性图标，统一 `stroke-width: 1.5`，圆角端点。

## 10. 技术架构

### 10.1 总体选型
| 层 | 选型 | 理由 |
| --- | --- | --- |
| 渲染 | **three.js + 自定义 GLSL** | 灵活可控大气散射与图层混合 |
| 球体纹理 | NASA Visible Earth / Black Marble / Blue Marble 公开切片 | 免授权、稳定 |
| 应用框架 | **Vite + React 18 + TypeScript** | 生态成熟，AI 协作友好 |
| 状态管理 | Zustand | 轻量、SSR 友好、好测 |
| 样式 | CSS Modules + CSS 变量 | 不引入 Tailwind，避免视觉熵增 |
| 测试 | Vitest（单元）+ Playwright（关键交互） | 覆盖 80% 路径即可 |
| 部署 | 静态站（Cloudflare Pages 或 Vercel） | CDN + 免费 + 易回滚 |

### 10.2 模块划分
```
src/
├── app/                  # 应用骨架、路由（v1 无路由，但留位）
├── scene/                # three.js 场景、相机、灯光、球体
├── layers/               # 图层系统（昼夜、云、海冰、城市灯光…）
├── timeline/             # 时间轴状态、播放、缩放
├── hud/                  # 顶部 HUD、底部时间轴 UI、浮层
├── data/                 # 离线切片数据加载与缓存
├── lib/                  # 经纬度换算、太阳位置计算等纯函数
└── styles/               # 全局变量、reset
```

### 10.3 关键算法
- **太阳位置**：基于时间与地球自转/公转参数的简化模型（精度够用即可，误差 < 0.5°）。
- **昼夜混合**：在片段着色器中按"地-日连线"做硬阴影 + 5% 软边带，避免锯齿。
- **图层切换**：所有图层独立 `THREE.Texture`，切换只改 `material.uniforms.uLayerMix`。

### 10.4 数据来源（v1）
- 地球基础纹理：NASA Visible Earth（公开域）
- 夜间灯光：NASA Black Marble 2016 / 2024
- 海冰：NSIDC 月度海冰浓度（v1.1 引入）
- 城市点位：Natural Earth 数据集（v1 即可用）

> 所有数据须在仓库 `data/` 目录或构建时下载，运行时**不联网**（除可选字体）。

## 11. 数据模型（最小集）

```ts
type CameraState = {
  lat: number;          // 相机纬度
  lon: number;          // 相机经度
  alt: number;          // 距地心距离（km）
  pitch: number;        // 俯仰角 0~90
  yaw: number;          // 偏航角
};

type TimeState = {
  utc: number;          // 时间戳 ms
  scale: 'hour' | 'month' | 'year' | 'century';
  playing: boolean;
  rate: number;         // 现实秒 / 地球秒
};

type LayerId = 'daynight' | 'nightlights' | 'clouds' | 'seaice';

type AppState = {
  camera: CameraState;
  time: TimeState;
  layers: Record<LayerId, { visible: boolean; opacity: number }>;
  selectedPoint?: { lat: number; lon: number; name?: string };
};
```

> 这是唯一允许跨模块共享的状态。任何局部 UI 状态必须留在组件内。

## 12. 接口与外部依赖

### 12.1 内置纯函数 API（必须 100% 单测覆盖）

### 12.3 不引入
- ❌ 任何后端服务（v1 纯前端）。
- ❌ 任何第三方统计 SDK（v1 不埋点）。
- ❌ 任何第三方账号体系（无登录）。

## 13. 边界情况与错误处理

| 场景 | 表现 | 处理 |
| --- | --- | --- |
| WebGL 不支持 | 检测 `WebGL2RenderingContext` 失败 | 静态兜底图 + 升级浏览器提示 |
| 纹理加载失败 | 局部纹理变红/紫马赛克 | 显示降级纯色 + 控制台 warn，不破坏交互 |
| 时间轴极值 | 拖到 1900 年之前 | 软回弹到 1900，时间标签变红 0.3s 提示 |
| 极端缩放 | 缩到地表以下 | 最低 100 km 高度锁定，相机抖动停止 |
| 极地翻转 | 跨越极点时方位突变 | 启用最短路径插值，避免画面翻转 |
| 长时间挂起 | 标签页休眠后恢复 | 时间轴自动暂停，恢复后弹"是否跳到现在" |

## 14. 度量与成功指标

### 14.1 北极星指标
> **TTE（Time To Earth）**：用户从打开页面到第一次主动旋转地球的时间。
> 目标：**≤ 10 秒**。

### 14.2 二级指标
| 指标 | 目标 |
| --- | --- |
| 首屏 TTI | < 3s |
| 平均会话时长 | ≥ 90s |
| 图层切换率 | ≥ 30% 用户至少切换 1 次 |
| 截图导出率（v1.1） | ≥ 10% |
| 30 天回访率 | ≥ 8% |

### 14.3 质性指标（每月抽 5 个用户访谈）
- 用户能否说出"刚才看到的是什么"？
- 用户是否主动拖动时间轴超过 3 次？
- 用户是否截图/分享？

> v1 **不接入任何分析 SDK**，指标靠问卷 + 自愿留邮件获得。
